# OutlookAI

OutlookAI - VSTO-надстройка для Microsoft Outlook. Она добавляет AI-помощника для написания и редактирования писем, чат по почтовому ящику, отчёты и экспорт данных.

Текущая ветка использует настраиваемый **LiteLLM**-коннектор. Надстройка обращается к LiteLLM-прокси с OpenAI-compatible API, а каждый пользователь указывает собственный ключ API в настройках OutlookAI.

## Конфигурация LiteLLM

Базовые параметры задаются при установке расширения скриптом:

- `LiteLlmBaseUrl`
- `Model`
- `VoiceModel`
- `Temperature`
- `MaxTokens`
- `MaxBulkExportRows`

`VoiceModel` необязателен. Если модель транскрибации не используется, оставьте значение пустым или укажите `null`; голосовая транскрибация будет отключена.

Пользователь указывает только:

- `LiteLlmApiKey`

Ключ API хранится отдельно для каждого пользователя в `%APPDATA%\OutlookAI\config.xml`. Он не записывается в общую машинную конфигурацию установки.

Используемые конечные точки:

- `<LiteLlmBaseUrl>/chat/completions`
- `<LiteLlmBaseUrl>/audio/transcriptions`

## Редактирование выделенного текста

В окне создания или редактирования письма, встречи либо задачи выделите текст и
откройте **Изменить выделение** на ленте или группу **Редактирование текста** в
панели справа. Ранее добавленное контекстное меню также сохранено.
Доступны официальный, строгий, дипломатичный и краткий тон, структурирование,
уточнение и ссылка на пункты переписки. После выполнения выделение
заменяется готовым текстом; в окне прогресса доступна безопасная отмена, а
замена также оформляется как единая операция Word для обычного `Ctrl+Z`.
Для понимания смысла в запрос передаются выделенный текст и до 6000 символов
до и после него; вложения и Outlook-инструменты для этих действий не используются.
Выделение остаётся активным. Неизменённые фрагменты сохраняют оформление,
изменённые наследуют основной шрифт. Гиперссылки (включая подписи и адреса)
защищены от переписывания. Текст внутри одной ячейки поддерживается; несколько
ячеек, объекты, служебные поля и включённая запись исправлений Word отклоняются.
Если Word не позволяет создать общую операцию отмены, текст не изменяется.

Список действий настраивается в группе **Редактирование текста** правой панели:
действия можно добавлять, редактировать, удалять, менять местами и сбрасывать к
исходным. Метаданные последних 200 применений и отмен локально хранятся в
`%APPDATA%\OutlookAI\text-action-history.json`; полные исходный и новый тексты
в историю не записываются. Статус `undone` записывается при отмене кнопкой в
окне результата; Word не предоставляет надёжного события для отдельного `Ctrl+Z`.

## Анализ переписки и скиллы

Действия анализа читают цепочку по Conversation ID, включая доступные отправленные
и архивные письма. Лимит — до 100 сообщений; при превышении сохраняются выбранное
и наиболее свежие сообщения, результат упорядочивается хронологически.
Панель сообщает о неполноте цепочки и сокращении тел. Содержимое вложений не читается.
Для открытого полученного письма и приглашения доступна кнопка анализа на ленте.

Шестерёнка правой панели открывает отдельные **Настройки · Скиллы**:
сотрудники/роли, процессы/правила и коммуникация. Локальный файл —
`%APPDATA%\OutlookAI\skills.json`, предыдущая сохранённая версия — `skills.json.bak`.
Импорт JSON сначала показывает новые записи и конфликты ID; замены выбираются явно.
Можно закрепить до пяти действующих скиллов для запросов этой панели.

Перед передачей знаний требуется прочитать уведомление. Модель получает каталог
названий/описаний через `outlook_list_skills`, а содержимое — через
`outlook_load_skill` (до пяти за вызов, десяти и 160000 символов за запрос). ИИ создаёт только
редактируемые черновики, включая предложения обновлений; запись происходит
после нажатия **Сохранить**. Текущая переписка включается в генерацию только
по отдельному флажку. В действиях замены выделения знания по умолчанию выключены;
их можно включить в настройке конкретного действия.

Явные назначения в письме важнее общего правила. Предположения, противоречия,
основания ответственности и сроков должны быть видны в ответе. Нет подтверждения
выполнения — не значит, что работа не сделана. Подробное логирование LLM, если
включено, сохраняет локально запросы/ответы, в том числе переданные знания.

Существующие пользовательские действия не перезаписываются. Новые тоны и
обновлённые базовые промпты появятся при новой установке или явном сбросе группы.

## Установка

Встроенной проверки и установки обновлений нет. Новая версия устанавливается
отдельным установщиком; сведения об установленном релизе сохраняются в `version.json`.

Для локального запуска без командной строки соберите единый EXE-установщик:

```powershell
.\Deploy\Make-InstallerExe.ps1 `
  -Tag v3.0.0 `
  -LiteLlmBaseUrl "https://litellm.company.example/v1" `
  -LiteLlmModel "company/outlook-chat" `
  -LiteLlmVoiceModel "" `
  -Temperature 0.2 `
  -MaxTokens 4096
```

Скрипт создаёт `out\OutlookAI-v3.0.0-Setup.exe`. Для сборки нужен MSBuild/Visual Studio с VSTO targets и встроенный Windows `iexpress.exe`; конечному пользователю Visual Studio для запуска готового EXE не нужна. Пользователь запускает этот файл двойным кликом; установщик сам запросит права администратора через UAC.

Для ручной или тихой установки можно опубликовать VSTO-сборку и запустить скрипт от имени администратора:

```powershell
.\Deploy\Install-OutlookAI.ps1 `
  -SourcePath "C:\OutlookAI" `
  -LiteLlmBaseUrl "https://litellm.company.example/v1" `
  -LiteLlmModel "company/outlook-chat" `
  -LiteLlmVoiceModel "" `
  -Temperature 0.2 `
  -MaxTokens 4096
```

После установки каждый пользователь открывает настройки OutlookAI и сохраняет свой ключ API LiteLLM.

## Структура проекта

- `VSTO2/OutlookAI/Services/LiteLlmChatService.cs` - коннектор LiteLLM chat completions, потоковая выдача и цикл tool-calling.
- `VSTO2/OutlookAI/Services/LiteLlmCredentialService.cs` - состояние пользовательского ключа API.
- `VSTO2/OutlookAI/Services/LiteLlmVoiceService.cs` - коннектор LiteLLM audio transcription.
- `VSTO2/OutlookAI/Services/Tools/` - слой Outlook-инструментов, который используется чатом и отчётами.
- `Deploy/` - установщик, скрипт удаления и инструкции по развёртыванию.

## Разработка

Проект использует .NET Framework 4.7.2 и VSTO. Для сборки надстройки нужен Visual Studio/MSBuild с установленными Office/VSTO targets.
На новом компьютере установите Visual Studio 2022 с рабочими нагрузками
**Разработка классических приложений .NET** и **Разработка для Office/SharePoint**,
**.NET Framework 4.7.2 Developer Pack**, .NET SDK и классические Outlook/Word.
Вместо полной IDE достаточно Build Tools 2022 с .NET desktop, Office/SharePoint
и отдельным компонентом **Visual Studio Tools for Office (VSTO) build tools**.
Один установленный .NET Runtime не содержит инструментов сборки.

Ручные проверки новой версии описаны в [чек-листе](docs/specs/2026-09-05-verification.md).

Тесты:

```powershell
.\Deploy\Test-Project.ps1

# После восстановления зависимостей — быстрый повторный запуск:
.\Deploy\Test-Project.ps1 -NoRestore

# Только интеграционные тесты редактора на настоящем Word:
.\Deploy\Test-Project.ps1 -NoRestore -WordCom -Filter 'FullyQualifiedName~WordSelectionEditorComTests'
```

Скрипт использует MSBuild с Office/VSTO targets, затем `dotnet test --no-build`.
Сборка для тестов не подписывает манифесты и **не регистрирует надстройку в Outlook**;
полученные DLL не являются готовым установочным комплектом. COM-тесты включаются
только явным `-WordCom`, создают отдельные экземпляры Word с несохранёнными
тестовыми документами и не открывают существующие документы или почту.
Первичные диалоги Word должны быть завершены пользователем. Результаты — `out/tests/tests.trx`.
